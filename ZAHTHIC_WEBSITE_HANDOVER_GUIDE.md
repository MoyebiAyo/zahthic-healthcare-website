# Zahthic Healthcare Solutions - Website Handover Guide

## Project Overview

Zahthic Healthcare Solutions is positioned as a premium healthcare, rehabilitation, wellness, prevention, and community impact organization. The website intentionally avoids a generic hospital-clinic feel and instead presents Zahthic as a trusted access, recovery, prevention, education, outreach, and partnership platform.

## How To Run The Site Locally

```bash
npm install
npm run dev
```

Open `http://127.0.0.1:5173/`.

## How To Build For Production

```bash
npm run build
```

The production output is generated in `dist/`.

## Main Content Areas

- Home: premium positioning, services, impact, SPACE Project, insights, partners, CTA.
- About: organization story, values, care philosophy, prevention/community impact positioning.
- Services: six core services plus individual detail pages.
- Projects & Impact: community stories, measurable impact placeholders, project detail pages.
- SPACE Project: flagship initiative page with vision, objectives, activities, gallery, impact, and partnerships.
- Partners: partner categories and inquiry form.
- Blog: article listing and article detail pages.
- Media Center: media filters and media detail pages.
- Recognition: spotlight and recognition entries with detail pages.
- Volunteer & Careers: volunteer, internship, and job inquiry form.
- Donate/Support: donation-ready intent flow and support form.
- FAQ: operational questions.
- Testimonials: placeholders until approved testimonials are supplied.
- Contact: booking/contact form with WhatsApp handoff.
- Admin: CMS schema preview, local CRM records, analytics events, publishing workflow, and integration readiness.

## Admin Preview Workflow

1. Visit `#/admin`.
2. Select a CMS model from the left menu.
3. Review required fields for content publishing.
4. Submit a public form to see a CRM record appear.
5. Use `Clear demo data` before handover or public demo sessions.

## Content Publishing Workflow

1. Draft: create or collect article/project/service content.
2. Review: confirm spelling, tone, medical sensitivity, and brand fit.
3. SEO Check: confirm title, excerpt, category, image alt text, and meta description.
4. Publish: publish through the connected CMS once production CMS is selected.

## Integration Notes

- CRM records currently save to local browser storage through `saveSubmission`.
- Analytics events currently save to local storage and `window.dataLayer` through `trackEvent`.
- WhatsApp links are generated by `buildWhatsAppUrl`.
- Newsletter capture uses the same submission pipeline.
- Donation is intentionally donation-ready, not payment-live.

For production, replace local capture with API calls to the chosen CRM, newsletter provider, analytics platform, and payment provider.

## Brand And Content Rules

- Keep language premium, human, practical, and impact-led.
- Avoid generic hospital phrasing such as "world-class hospital", "medical department", or overly clinical language unless the service genuinely requires it.
- Use verified numbers only for impact stats.
- Use approved testimonials only after consent.
- Keep imagery primarily African/Black, dignified, real-world, and care/community focused.
